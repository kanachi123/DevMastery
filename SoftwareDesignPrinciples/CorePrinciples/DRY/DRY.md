в чем логика

когда пишешь архитектуру или код,или что то похожее иногда случается так что ты дублируешь батчи кода,то есть блоки кода
их часто удобно выносить в функции либо методы обьекта...

или например если занимаешься метапрограммированием ты используешь темплейты чтобы обобщить на дедуктивный случай чтобы не повторятся и написать универсальный код...

но есть ситуация когда ты впринципе можешь повторятся когда нет смысла написать сложную абстракцию для не масштабируемой системы потому что чем сложнее абтсракция тем сложнее профилирование,а это станет сложно для другого программиста читаюшего твой код

чтобы решить эту проблему есть такая штука,она называется  **AHA(Avoid Hasty Abstractions)**  

# **например нарушением DRY считаются магические числа**  

*Магические числа в программировании — это числовые значения прямо в коде, смысл которых непонятен другим людям (и вам через время). Это плохая привычка, из-за которой трудно искать ошибки и менять настройки*  


```
Сначала пишем DRY-код. Затем смотрим, что сгенерировал компилятор. Если профилирование показывает, что вызов функции — узкое место, можно локально нарушить DRY ради производительности
```  

```
Не копируй код = не пиши одно и то же действие два раза.
Не копируй знания = не храни одно и то же правило в разных местах  
```  


*если в коде что то поменяется и ее очень много ты будешь профилировать очень долго,
для этого лучше использовать обощающие штуки,
как структуры методы валидации с булевыми значениями,указатели ссылки,макросы,батчи,темплейты,агрегация,кластеризация,написание дедуктивных систем где ты из общего
приходишь к частому*  

```

userName = "Alex";

```  

```
Ты будешь перебирать каждый раз отдельные данные в аргументах это неудобно не читаемо говно добавляет лишние строки получается спагетти код

SendEmail(userName);
CheckAccess(userRole);
ShowProfile(userAge);

```  

## вместо этого лучше лучше написать структуру или класс пользователя и дать как аргумент ссылку на пользователя и в методах вызвать уже оттуда нужные данные

```

struct User
{
    string name;
    int age;
    Role role;
};

SendEmail(user);
CheckAccess(user);
ShowProfile(user);

```
